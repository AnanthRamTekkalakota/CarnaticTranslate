The short version

CarnaticTranslate does not require a separate CarnaticTranslate account. Transcribing a page sends its source image and instructions for cloud AI processing. Beta processing and earlier provider routes are described below; the planned public release will use Anthropic Claude Haiku across all plans. Your saved library stays on your device or, if you opt in, in your iCloud account.

The beta service uses operational, security, purchase and recovery records. Where server response recovery is enabled, a successful response is stored temporarily in encrypted form. The app does not include third-party advertising, analytics or crash-reporting SDKs.

This website presents information and support links; it does not accept scan uploads or offer an App Store download. If you email support, we receive your email address and the information you choose to send.

Website hosting

This site is hosted on GitHub Pages. GitHub logs and stores visitors’ IP addresses for security purposes, including visits without a GitHub sign-in. See GitHub Pages data collection and GitHub’s Privacy Statement. We do not add advertising or analytics scripts to this site. Following an external link or emailing support uses that service’s own processing.

Source images and AI transcription

For app-supplied transcription, the app sends each selected page, transcription instructions and any multi-page continuation context through our Cloudflare Worker. Depending on the beta service configuration, the Worker authenticates the request, applies technical and page-allowance checks, forwards the image and instructions to the configured AI provider, and returns the response. Each provider processes the data under its applicable API or commercial terms.

The Worker buffers the request and response while processing. Its application code does not deliberately write source images or prompts to operational logs or ordinary allowance records. Successful responses may be retained separately for recovery, as described below. Cloudflare also handles network and infrastructure processing; this application-code description is not a promise about every Cloudflare internal or account-level retention practice.

AI providers and routing

Beta versions: the beta service supports an automatic Anthropic Claude Haiku route. Earlier beta builds and service configurations also supported OpenAI and Google’s Gemini API; a request made through one of those versions or routes is subject to that provider’s practices. The build and service route determine processing. This does not mean every page goes to all providers or that every beta user can select a provider.

Planned public release: bundled transcription is planned to use Anthropic Claude Haiku across Free, Standard and Plus. The service selects the model; bounded retries stay with the same model rather than falling back to another AI provider. The public release is coming soon.

Earlier custom-endpoint versions: if you use a beta version that supports a configured custom endpoint, it sends the image, instructions and endpoint credential directly to that operator instead of our Worker. The operator’s terms and privacy practices apply. An OpenAI-compatible API format does not mean OpenAI operates the endpoint. Custom endpoints are not an advertised feature of the planned public release.

For provider terms and data handling, see Anthropic’s Commercial Terms, OpenAI’s API data controls and Services Agreement, and Google’s Gemini API terms. Changing a provider does not erase copies already held by an earlier provider or endpoint operator.

Short-term Worker result retrieval

Where response recovery is enabled, the Worker stores the successful response returned to the app and the served-model value as application-encrypted ciphertext. Depending on the route, the response may include provider-format metadata, such as token usage. The source image and prompt are not included in this recovery payload. A matching request from the same pseudonymous owner, operation and input can retrieve the result for up to 15 minutes without another provider call or page charge.

Retrieval eligibility is separate from deletion. The Worker implementation makes expired ciphertext and its encryption IV eligible for active cleanup by an alarm or a later cleanup/admission operation; this is not a guarantee of deletion at the exact expiry time. Operation IDs, input hashes, allowance links, operation state and expiry/deletion timestamps can remain without an application-level expiry.

Cloudflare’s SQLite-backed Durable Objects support point-in-time recovery of earlier state within the previous 30 days (SQLite storage and PITR documentation). Removing active ciphertext does not remove historical backup or restore copies. We do not promise that every beta environment has identical recovery settings or that expired results can still be recovered.

Operational records and identifiers

Beta versions of the app and Worker use pseudonymous identifiers to secure the service, enforce page allowances, and make retries idempotent. These include a random device UUID stored in Keychain, an Apple App Attest key and receipt, a per-page operation UUID, a random Worker request ID, server-created owner and account identifiers, and HMAC-derived Apple transaction lookup keys. Cloudflare also processes ordinary network metadata, such as IP addresses, when delivering requests. The Worker uses the raw device UUID and IP address transiently to derive throttle selectors; our custom logs do not include the raw device UUID or IP address.

Depending on the enabled beta features, Worker storage contains App Attest registration and counter state, opaque owner bindings, subscription grants and dates, page usage and reservations, throttle counts, and operation records. Raw Apple transaction identifiers, signed Apple proofs, notification bodies, source images, prompts, and transcription text are not deliberately stored in these records. Except for the specific expiring records described in this policy, these pseudonymous service records currently have no application-level deletion schedule or user deletion endpoint.

The Worker implementation emits custom operational logs for requests. Depending on the route, these logs may include the random request ID, route and outcome, requested and served provider/model, provider status, latency and duration, fallback or retry result, token counts, finish reason, App Attest outcome and timing, plan and allowance counts and dates, and the page operation UUID. They do not deliberately include images, prompts, transcription bodies, provider credentials, raw Apple proofs, or raw Apple transaction identifiers. Logging behavior depends on the beta service configuration. Cloudflare account settings and plan determine how long Workers Logs remain available and whether any account-level export exists; the application source does not configure a log export. This does not establish the absence of account-managed exports or other operational copies.

AI-provider use and retention

Provider handling is separate from our Worker storage. Anthropic’s published Commercial Terms state that it may not train models on customer content from the services. Its standard API policy deletes inputs and outputs within 30 days, with exceptions for agreed arrangements, features with longer retention, safety enforcement and law; some covered models have additional retention/review requirements. See its API retention policy and exceptions.

These are the provider’s published defaults, not confirmation of a special retention or training arrangement on the account used for a particular beta request. We do not promise zero data retention or different data treatment for Free and paid plans. Consumer chatbot settings do not establish API handling. Earlier OpenAI, Gemini and custom-operator processing follows the applicable terms linked above.

Saved documents and source images

Saved documents contain the transcription, metadata you enter (such as title, ragam, talam, and composer), and references to downscaled source-page images. The document JSON and source images are stored in the app's document storage. Generated PDFs are derived files kept in a local cache. The Worker does not become the primary storage location for your saved library.

Optional iCloud sync

iCloud sync is optional and off by default. If you enable it, document JSON and associated source-page images move to the app's iCloud ubiquity container and can appear on your other devices using the same iCloud account. Generated PDFs remain in the local cache. Apple handles iCloud data under its own iCloud terms and privacy policy. Turning sync off leaves existing iCloud copies in place. Saved document JSON and source images may also be included in device or computer backups; the exclusions below apply to managed working and recovery files, not the primary saved library.

Local migration backups

When the app successfully copies and verifies a local document or image during migration to iCloud, it moves the local original to a migration-backup folder and records its provenance. A verified, recorded migration backup becomes eligible for cleanup seven days after verification. Failed or unverified migration originals do not become cleanup candidates. Older or legacy files whose provenance is unknown also remain protected because the app does not infer ownership from age or filename alone. The managed migration-backup folder is excluded from device backup, but that exclusion cannot remove copies already present in historical backups or snapshots.

Unfinished scans and temporary exports

In beta versions supporting background scanning and recovery, the app stores prepared source-image files, exact serialized request bodies, page operation IDs, settings, completed page results, status and error information, retry counts, and timestamps on the device. These working files are excluded from device backup. Completed working state can be removed after a successful document save or explicit discard. Failed, interrupted and unsaved work is retained for recovery or review. Versions with protected recovery context can hold uncertain legacy jobs rather than resend them automatically; reviewing or saving their completed pages does not itself discard the unresolved job.

Exports are created as temporary local files. A file being actively shared is protected from cleanup. When sharing finishes, the app attempts immediate removal. If removal fails, or if a prior-process share can no longer be treated as active, the file is marked abandoned and becomes eligible for cleanup after 24 hours.

iCloud conflict recovery

When iCloud reports conflicting document versions, the app selects the newest JSON version and first archives each losing JSON version in device-local Application Support. These archives are excluded from device backup and do not sync across devices. They preserve document JSON only; referenced source images are not copied into the archive. Recovery creates a new document without those source images. An archive becomes eligible for cleanup after 30 days, unless it is actively being recovered.

Deletion and remaining copies

When iCloud sync is active, deleting a document removes its active JSON, referenced source images, and cached PDF from the active stores and requests deletion from iCloud so the change can propagate to devices with sync enabled. When sync is off, unavailable, or unresolved and the app is using local storage, deletion removes only the local active copy. A copy left in iCloud may reappear if you enable sync again.

Deleting a document in the app concerns its active local and, when sync is enabled, iCloud copies; it does not delete Worker account, allowance, security, or operation records. The service does not currently provide an authenticated in-app workflow to request deletion of developer-held server data. You may contact Ananth Ram Tekkalakota at razer323@hotmail.com with questions or requests concerning your information, including access, correction or deletion where applicable. Do not email receipts, signed Apple proofs, API keys, passwords or device identifiers. Email is not an authenticated deletion service: sending a request does not itself verify ownership or erase service records. It is not an automated deletion command and does not by itself delete data. No immediate or complete erasure is promised.

Apple subscription cancellation is separate from both document deletion and a privacy request. Manage or cancel an App Store subscription in Apple’s subscription settings; deleting documents, contacting us, or removing the app does not itself cancel it. Active deletion by us or Apple does not necessarily remove historical platform backups or provider retention copies. Those copies may remain under the applicable platform, provider or account retention rules; a local deletion does not control them.

Before removing managed conflict archives for a deleted document, the app records a local deletion tombstone. If physical archive removal fails, the archive is hidden from recovery and cleanup is retried so that managed archive cannot recreate the deleted document. Explicit document deletion also attempts to remove migration backups whose ownership is established by recorded metadata. Unindexed legacy archives, unknown-provenance migration backups, copies already present in device or iCloud backups or snapshots, and other copies outside the active store may remain. Deleting active data does not erase those historical backups, and their retention and purge timing are controlled by the operating system or backup provider.

When local cleanup runs

The local cleanup behavior described here is implemented in the beta storage code. Older beta versions or copies created before that implementation can retain additional files; a policy update alone does not delete them.

Seven-day, 24-hour, and 30-day periods in this policy describe when a local item becomes eligible for cleanup, not a guaranteed deletion time. Cleanup runs at safe app-execution opportunities, including launch and return to the foreground. The app cannot promise cleanup while it is closed, and failed deletions retain lifecycle metadata so they can be retried later.

Credentials

Provider credentials and background-job keys retained by earlier custom-provider or bring-your-own-key versions, and the stable device UUID are stored in Apple Keychain with after-first-unlock accessibility so background recovery can operate after the device has been unlocked once. The app migrates the former plaintext custom-provider key from preferences to Keychain and removes the preference only after the Keychain copy is verified. If migration fails, the legacy value is retained so it is not lost. Removing a live plaintext preference cannot erase copies that may already exist in historical device or iCloud backups or snapshots.

On-device diagnostics and notifications

The app emits local console and performance-signpost diagnostics used to operate and debug app features. Depending on the build and action, these can include the backend environment and URL, requested or served model, HTTP status, duration, random Worker request ID, error category or message, App Attest outcome, StoreKit product IDs and coarse verified-state evidence, scan page and task counts, parsing structure, export format and document structure counts, byte counts, and an exported file's name and local path. The app does not send these diagnostics to a third-party analytics or crash-reporting SDK. Device and development tools may retain or expose local logs under their own settings. If you enable notifications or Live Activities, the app may display a transcribed song title on the lock screen when reporting scan completion.
